# 青栏前端生产化改造方案

# 背景与目标

## 改造动因

对现有前端（qinglan\-web / qinglan\-admin / shared）的页面与逻辑，当前存在三类明确不满，均指向同一个问题：视觉与产品形态停留在「演示级」，未达到生产级内容社区的标准。

- **交互流程：**认证走三步向导加步骤条，操作路径长；发帖、详情等主流程缺草稿、缺加载更多等社区惯例交互。

- **信息流与内容组织：**信息流只有时间倒序单一排序，无热门维度；首页以「头条大卡 \+ 卡片列表」呈现，内容组织方式不符合社区预期。

- **功能范围：**学生端仅 6 个页面，缺「我的帖子」「发帖草稿」「举报反馈状态」等社区必备功能，整体偏功能演示而非可用产品。

同时，现有视觉语言「AI 味」明显（渐变 hero、毛玻璃、胶囊徽章、卡片浮起），需要一套适配生产、克制且可维护的社区界面语言。

## 现状判断

前端工程层已经达到生产级：composables 职责拆分清晰、错误统一由 http 拦截器出口、页面状态严格区分 loading / failed / empty / content 四态、响应式与可访问性处理到位、每个页面均有单测覆盖。本次改造**保留工程层不动**，问题集中在视觉语言与产品形态两层。

# 改造方向与取舍

## 三个候选方向

|方向|参照物|视觉特征|判断|
|---|---|---|---|
|**A 社区信息流型**|贴吧 / NGA / 即刻|白底分割线列表、高信息密度、无装饰、单色强调|去味最彻底，最适配匿名内容社区；执行成本中等，密度需做到位|
|B 校园清爽型|豆瓣 / 超级课程表|品牌色克制点缀、轻卡片、大量留白|观感温和，但轻卡片与留白仍是模板语素，去味不彻底|
|C 极简工具型|Linear / Notion|黑白灰为主，排版本身说话|最克制，但偏冷，学生产品易显生硬|

## 选择方向 A 的理由与代价

**理由：**青栏本质是匿名 UGC 内容社区，用户进入产品的任务是「看内容」。贴吧、NGA、即刻验证过的社区界面语言（分割线列表、内容优先、低装饰）最适配生产，也最能承载后续的话题页、热门榜等功能扩展。

**代价：**高密度排版对设计执行要求高，密度失衡会显拥挤；与现有卡片风格差异大，视觉冲击强。通过阶段 1 先收敛 token、阶段 2 再重做页面来缓解。

# 核心页面重做（阶段 2）

## 首页

**现状问题：**hero 横幅占首屏；头条大卡与紧凑行混合形态；信息流只有时间倒序。

**新结构：**顶栏（Logo \+ 话题横导航 \+ 发布入口）→ 最新 / 热门 Tab → 分割线列表（话题 \+ 内容摘要 \+ 配图 \+ 互动数据一行排开）→ PC 右栏话题导航、窄屏话题 chips。

**关键交互：**话题切换重置列表回到第一页；Tab 切换保留当前话题；加载更多沿用现有游标分页。

## 详情页

**新结构：**帖子主体（正文 17px、配图、互动条）→ 评论区分割线列表 \+ 「加载更多」（配合第 6 章评论分页）。下架帖保留下架原因展示与申诉入口。

## 发帖页

**新结构：**话题单选（卡片式，展示该话题规则与是否要求联系方式）→ 正文大输入框 → 图片九宫格（最多 9 张）→ 联系方式按话题要求显隐 → 提交前草稿自动保存到 localStorage，意外退出不丢内容。

## 认证页

**新结构：**单卡内联：输入邮箱即发码 → 输入验证码即登录 → 新用户就地补学号完成。去步骤条；管理员身份提示保留（沿用现有逻辑）。

# 信息流与内容组织（阶段 3）

- **最新 / 热门双 Tab：**热门用「点赞 \+ 评论数 \+ 时间衰减」权重（建议 score = 点赞数 × 1 \+ 评论数 × 2，再乘时间衰减因子 e^\(−年龄/72h\)），后端新增 sort=hot 排序参数，不破坏现有游标分页。权重口径待产品确认（见第 11 章）。

- **统一列表行：**首页头条大卡与紧凑行合并，列表信息密度与内容组织对齐社区惯例。

- **话题筛选保留：**现有话题横导航与右栏话题栏语义不变。
