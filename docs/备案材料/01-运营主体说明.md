# 青栏 Qinglan 运营主体说明

> 本文档随系统实现同步更新。本文档用于向校方及主管部门说明平台的运营主体、服务对象、技术边界与内容治理投入，是平台备案与上线审批的配套材料之一。

## 一、平台性质与定位

青栏（Qinglan）是一个面向**本校在校学生**的匿名信息交流社区，定位为校园信息基础设施，而非民间匿名投稿账号或商业化的"表白墙"。平台的全部功能围绕"认证学生之间的公开信息交换"展开：发布帖子、二级评论、点赞、举报、申诉、公告通知。

平台"匿名"的含义是**前台匿名、后台实名**：作者在帖子中展示的是系统派生的随机代号，不对其他用户展示真实身份；但每一位可发帖的用户都必须先通过校园身份认证，平台在后台保有可追溯的认证记录。平台不接受任何人以系统运营者名义代为发布、转发或"投稿"内容。

## 二、服务对象与准入

### 2.1 服务对象

本校在校学生，且已完成校园身份认证。未认证用户（含游客）只能以只读方式浏览已审核通过的内容，不能发帖、不能评论、不能举报、不能查看联系方式。

### 2.2 准入流程

平台**不对外开放注册**，认证按下列步骤进行，两步缺一不可：

1. **校园邮箱验证**：用户提交校园邮箱，系统向该邮箱发送 6 位数字验证码（有效期 5 分钟，60 秒后方可重发，单次验证码最多校验 5 次，超限即作废）。仅当邮箱域名命中**校园邮箱域名白名单**时才允许发送。白名单必须由运营方显式配置；未配置白名单时系统拒绝全部邮箱（fail-closed，即"默认拒绝"），不存在"配置遗漏导致校外邮箱可注册"的可能。
2. **学号绑定**：用户提交学号，用于"一人一学号"的唯一绑定。学号经不可逆哈希后建立唯一约束，同一学号不可重复绑定。

认证一经完成不可改绑，以保证"一人一校、一人一号"。

### 2.3 前台身份

前台展示的匿名代号由系统按 `hash(帖子 ID + 作者 ID + 该用户专属盐值)` 派生，因此**同一用户在不同帖子下的代号必然不同，跨帖无法关联**。平台对外接口不会同时返回用户的匿名代号与其内部账号标识。

## 三、技术边界（明确不做）

平台在设计与实现上明确排除以下能力，相关代码路径不存在：

- **不开放注册**：无邮箱白名单外的注册入口，无邀请码、手机号注册等旁路。
- **不跨校可见**：邮箱域名白名单限定为单一学校，不存在跨校内容互通或跨校用户。
- **不做私信**：系统不提供用户间一对一私信功能，避免匿名骚扰通道。
- **不做付费**：无付费推广位、无付费代发、无任何付费内容与充值功能。
- **不做商业推广**：无广告位、无商家入驻、无带货与拼团交易撮合。
- **不做"匿名投稿 / 隔空喊话 / 捞人"专版**：不设此类版块或话题。
- **不做图片内容识别与人脸识别**：图片治理采用"发布轻审 + 事后举报下架"模式，不采集生物特征。

## 四、内容治理投入

平台建立了从发布前拦截到事后处置的完整治理链条，全部机制在系统中实际运行：

| 环节 | 机制 |
| --- | --- |
| 发布前硬拦截 | 敏感词库命中即拒绝发布；隐私信息正则拦截身份证号、银行卡号；单帖图片不超过 9 张、单张不超过 5 MB |
| 主帖先审后发 | 帖子先进入待审状态，须经人工审核通过后才对其他用户可见，驳回时向作者显示理由 |
| 审核队列 | 管理端以举报队列为主视图，按**待处理举报数 + 等待时长**排序，供管理员集中处置 |
| 举报机制 | 任何认证用户可举报帖子或评论；同一用户对同一目标仅可举报一次（数据库唯一约束保证，重复举报被明确拒绝而非静默忽略） |
| 自动下架 | 单个帖子待处理举报数达到 **3** 条时，系统自动将其下架并转入人工复核，同时通知作者 |
| 处置手段 | 通过、驳回、下架、恢复、隐藏联系方式、撤销隐藏、移除评论、驳回举报、维持下架 |
| 申诉复审 | 被下架帖子的作者可在 7 日内申诉一次，由**另一位**管理员复审，原处置人不得复审自己的裁决 |
| 审计留痕 | 下架、恢复、封禁、隐藏联系方式、公告发布、查看联系方式等动作全部写入审计日志；审计日志只增不改不删 |
| 上传限流 | 单个用户每分钟最多发起 30 次上传，防止对象存储被刷 |

## 五、数据处理与学生身份保护

平台的运营方**不具备查看学生真实身份的技术能力**，这一点由系统结构保证，而非仅靠管理制度约束：

1. **学号加密存储**：学号以 AES-256-GCM 加密写入数据库，每次加密使用随机初始向量，同一学号两次加密结果不同，无法被直接比对。解密能力仅保留给依法配合调查的专用通道，该通道不接入任何管理后台、日志或导出功能。
2. **邮箱只存不可逆哈希**：校园邮箱以 SHA-256 加固定 pepper 哈希后入库，数据库内不保存邮箱明文，无法从库中反推邮箱地址。
3. **管理员界面不返回身份字段**：管理端的用户列表只包含用户标识、角色、账号状态、信用分、封禁到期时间与注册时间，不含邮箱、学号明文或密文。该约束由对外用户档案 DTO 统一实现，普通接口与管理接口复用同一份结构。
4. **审计日志保留不少于 6 个月**，且只增不改不删，符合违法信息处置的存证要求。

## 六、上线前置条件

**在取得校方书面授权与完成主管部门备案之前，平台不得上线运营。** 具体前置条件包括：

1. 由校方（学生工作处 / 党委宣传部等主管单位）出具书面同意，明确平台由校方背书运营；
2. 完成运营主体备案，明确运营主体名称、责任人与联系方式；
3. 明确内容审核的人力安排与值班机制，保证举报在承诺时限内得到处置；
4. 本材料清单中的社区公约、审核规则、隐私政策、投诉举报入口随平台一并公示。
